## 2026-11-14: The results site's 3D files and failure drawings follow the saved findings (no result changed)

After the Estoa regrade (#20), CI failed twice on `tests/test_results_site.py`: the committed failure drawings, the judge's audit of them and one reason photo still described checks the regrade had changed. Two bugs in the scripts that make them were behind it: `scripts/results_site_media.py` and `scripts/results_site_views.py` reused a design's saved record whenever its VERSION matched, so after a regrade a re-run redrew nothing; and a run over some designs (`--only`) rewrote the committed manifest from the local records alone, which would have dropped about 600 of the drawings' 690 designs on a machine without every record.

- **Content keys.** Each design's files are made from its submission, saved findings (and which file holds them), assumptions and its task's spec files. Their hash with the script's VERSION is the design's content key, stored in each local record and under each committed manifest's `keys`. A run does only the designs whose committed key isn't current, and reuses a local record only when its key matches. A regrade that leaves the findings as they were leaves the key alone.
- **Overlaid manifests.** What a run did is laid over the committed manifest, so every other design is kept; designs no longer under `results/runs` are dropped, and so is a design whose checks now all pass.
- **The audit is pruned.** Audit answers for drawings that were replaced are dropped. The new drawings stay unaudited until the audit is rerun.
- **`--check`.** Both scripts exit 1 when a committed entry (or, for the drawings, an audit answer) is out of date, drawing nothing and needing no network. `scripts/update_tables.sh --check` (run by `reproduce.sh`) runs both, and `tests/test_site_files_current.py` runs them on the committed manifests in CI, so a regrade that leaves the site behind fails with the command that fixes it.
- **Reason photos for reasons no design has now** are kept in `scripts/results_site_references.json` but not shown, instead of failing the site's tests. The photo of Dan's bent insert post, taken out in #20 when R4 started passing, is back in the file for when R4 is tightened.
- `results_site_media.py` now stops at the start when pyvista is missing, instead of saving every design as unbuilt; writes its manifest only once every file it names is uploaded, as the drawings script already did; and rebuilds a design's parts when its submission changed, instead of reusing the old meshes.
- A `--failed-only` drawings run never becomes a committed entry, since it leaves out the ungraded checks' drawings.
- Shared inputs (the catalog, the site's caption tables) aren't in the key: a change to them needs a VERSION bump to redraw.

Keys were stamped once on the entries already made from today's saved files: those whose findings and submission are unchanged since the manifest was drawn, plus the drawings redrawn in #20. The rest were redrawn and uploaded. Tests: `tests/test_site_files_current.py`.
