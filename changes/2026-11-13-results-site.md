## 2026-11-13: A results site that shows every saved trial (no result changed)

The saved runs can now be browsed at https://oveddan.github.io/functional-print-eval/. A reader picks a condition (first print, after one round of feedback, asking for test prints first) and a part, then opens any model's trial: the render of each part with the failing region in red where a grader can locate it, a 3D view, every check with its reason, cost, tokens, the slicer's estimates, the measurements and test prints it asked for with the simulated person's answers, the second print beside the first, its code and a transcript excerpt. No verdict, `grades.json` or `summary.csv` changes, and no model was called.

- **`scripts/results_site.py`** writes the site to `results/local/site/` from the saved runs in about 20 s, with no part built. It reads verdicts, second prints, test-first trials and estimates through `scripts/scorecard.py`'s own functions and takes each non-passing check's reason from `scripts/results_page.py` and `scripts/failure_tables.py`. 1196 entries: 852 graded trials, 334 replay arms and 10 crash replays. Entries the scorecard leaves out are shown and flagged with the reason: 41 test-first trials stopped by out-of-credit errors, Grok 4.7's 2 first prints, and 51 second prints whose first print passes after a later regrade. Home-folder paths, key patterns and the provider's account id in error text are redacted from what's published.
- **`tests/test_results_site.py`** (13 tests, about 10 s) checks that the site's passes and trials equal `scorecard.rows()` per model and part for first print, after feedback and test-first; that every saved trial, loop arm and crash replay appears exactly once; that a not-graded trial is never counted as a pass; and that the not-graded reason counts equal `failure_tables.tally()`. The page repeats the check in the browser (`window.resultsSiteCheck`): 1664 comparisons equal, including each of the 147 scorecard links opening a list with the cell's own numbers.
- **`scripts/results_site_media.py`** rebuilds each saved design's parts (`parts/` isn't committed), renders a thumbnail per part, exports a mesh for the 3D view and uploads both to the media host; `scripts/results_site_media.json` records the links. 1145 designs found, 1101 built (34 stop on an error in the model's own code, 10 replays hold only test prints), 1949 parts. A red region is drawn from the grader's own geometry for `bridges` (318 parts), the nut pocket that the knob's R3 and R4 read (125) and `connected_bodies` (27); the other checks have no function that locates the feature, and the page says "not shown on the picture" for them. 93 Estoa designs have an assembled view from `scripts/assembly_scene.py`. These are renders of designs, not prints: nothing a model designed was printed.
- **`scripts/results_site/`** is the page: plain HTML, CSS and JavaScript modules that draw everything from the generator's JSON, with no build step. Links carry the view (`?cond=&task=&verdict=&model=&reason=&trial=`).
- **`.github/workflows/site.yml`** builds the site on every pull request and publishes it to GitHub Pages from `main`.
- **Review.** Two reviewers who weren't shown the design's rationale went through the page at phone and desktop width; their findings and what was done about each are in the pull request. Still weak: the red region is hard to see at thumbnail size for colour-blind readers (needs a re-render), Estoa's failures are marked only in the assembled view, and the 3D view was checked in Chrome with emulated touch only.
