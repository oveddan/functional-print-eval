## 2026-11-13: The changelog is built from one change file per PR (no result changed)

- Every PR added its entry to the top of `CHANGELOG.md`, so any two open PRs conflicted there on every rebase. Each PR now adds its own file, `changes/<YYYY-MM-DD>-<slug>.md` (format in `changes/README.md`), and no two PRs touch the same file.
- `scripts/changelog.py --write` builds `CHANGELOG.md`: the change files newest first, then `changes/history.md`, which holds every entry written before this one, unchanged. `CHANGELOG.md` is git-ignored rather than committed, because a committed generated file conflicts just like a hand-edited one, and keeping it current on `main` would need a bot pushing to `main`. Built today, it matches the last committed `CHANGELOG.md` line for line apart from one added line in the header saying where it comes from.
- CI gets a `change file` job: it fails a PR that changes `results/`, `pbe/graders/` or `catalog/` without adding a change file, or that adds a badly formed one. It fails rather than warns because `CLAUDE.md` already requires an entry for every change that affects results, and a warning on a green PR is easy to miss. A change under those paths that moves nothing still gets a short "(no result changed)" entry, as before.
- `CLAUDE.md`, `docs/overnight-runs.md`, `docs/scoring.md`, `docs/reference.md`, `docs/plan.md`, `docs/lessons.md`, `docs/limitations.md` and the comment in `tests/helpers.py` point at `changes/` now. Tests in `tests/test_changelog.py`.
