## 2026-11-14: Results site: a "How the checks work" page, with a passing and a failing design for each check explained (no result changed)

Dan asked for documentation of what the tests test, by example, with renderings of the test and the failure, and said he didn't know how a failure is decided. The site now has `checks.html`, linked from the home page's header, from "How to read a result", and from each check's id in a trial's detail when that check is explained.

- **What's on it.** An opening on the overall shape (nothing a model designed was printed; code measures each design and compares it with Dan's recorded test prints; pass, fail, not graded and not reached; a design passes only if every counted check passes; the 0.2 mm nearest-print rule). Then 11 checks, the commonest and most instructive across the four scored tasks: `builds`, `bridges` and `connected_bodies` on every part; the knob's R3 and R4; the wheel's R3; the tripod plate's R2, R3 and R4; the Estoa box's R1 and R6. For each: what it tests in plain words, the steps the grader takes with its real thresholds, links to the grader functions at the pinned commit, the recorded prints it rests on, what not graded means for it, where it's weak, saved designs that pass, fail or aren't graded with the drawing of what the check read, Dan's photo of a real print where one shows the failure, and links to the first prints that fail each way.
- **Where it comes from.** The prose is one reviewed file, `scripts/results_site_checks.yaml`, each entry naming the grader file and function it describes. `scripts/results_site.py` writes `data/checks.json` from it, with counts read from the same issue rows the home page counts and examples read from the saved findings, so they can't drift. All 24 drawings are made for this page from today's code by `scripts/results_site_check_views.py`, with the views script's own drawers (its own for `bridges` and `connected_bodies` on a passing part, whose drawers look only for a failure, and for Estoa's R6, whose drawer in `scripts/results_site_views.py` still calls the keyhole functions PR #20 removed), uploaded to the media host and recorded in `scripts/results_site_check_views.json`. The images carry no caption, so a card doesn't print the finding twice; the caption is their alt text. The passing examples are saved first prints where the check passed, mostly Opus 5.5's (the tripod plate's roof is Gemini 4 Argon's trial 3, because Opus's plate has no overhang to draw), each from a design that passes overall. The reference solutions weren't used: they aren't saved trials, so they have no page to link to.
- **Tests.** `tests/test_results_site.py` checks that every named grader function exists, that every example is a counted first print whose check has the stated outcome today, that every non-`builds` example has a drawing in the state it's shown for, that a pass resting on a test print or template is labelled, that each section's counts account for every design in its denominator exactly once, that a trial's checks link to existing sections and only explained checks link, and that the committed manifest holds media-host URLs only. A regrade or a grader change that moves an example fails there, as PR #20 did.
- **Corrected after PR #20 and a fact-check against the code.**
  - *R6 (Estoa keyholes)* rewritten for #20's rule: a keyhole hangs if one of five common nails or screws fits it (head through the entry with 0.4 mm to spare, shank in the slot, slot narrower than the head); entry and slot size limits and the plastic-thickness test are gone. No counted first print fails R6 now, so the fail example (Haiku 5.5, trial 2, 9.5 mm entry) became the pass example with that history noted, and the not-graded example is DeepSeek V4 Pro's trial 1 (no keyhole found).
  - *R1 (Estoa disk holes)*: the board is now taken as 1.6 mm. The template rule is described as the code has it: any template or test-print criterion and any parameter it names that changes the plastic behind the holes by more than 0.5 mm² when moved 1 mm, without checking that the test is about hole positions. Opus 5.5's trial 2 passed that way on an insert test and the insert hole's diameter; it's now shown labelled "Passes, by the template rule", and GPT-6.1 Sol's trial 3, which passes on its holes as drawn, is the plain pass. 11 of R1's 16 first-print passes rest on the template rule. Not graded now also lists a disk not placed once, no assembly and an unreadable mesh.
  - *bridges*: #20 counts a strand lying wholly within 1.5 mm of the layer below as landing; added. "A hole through a roof fails in every direction" now says a small holed roof can pass by the short-strand rule, and that rule's second print is quoted as recorded ("mostly ok; a few strands"), not as clean.
  - *knob R4*: +0.30 M5 is recorded as loose, not fell out; the page now says the check reads it as fell out from the earlier PETG tripod build. The plain M5 pockets at -0.15 to -0.05 are attributed to round 3's I (U1 to U3), round 1's B is 0 to +0.30 in 0.1 mm steps, and the record says what was done (B's +0.20 and +0.30 never turned over; round 3's pockets pressed on with a bolt, counted as going in by Claude's scoring call). The test-print rule accepts a single pocket. R4 still grades a pocket R3 found closed; the count is shown.
  - *wheel R3*: every plain seat gets a pass or a fail (the gaps between records are narrower than 0.2 mm); only a ribbed seat or none is not graded. Round 3 says "too loose", not fell out, and the page notes that the grader's own wording says fell out.
  - *tripod R3*: the 15 mm head-through limit is marked as the brief's inference, not a print.
  - *Opening*: states now include declined and no design, a crash of a check's own code is recorded as a fail (shown per check), not reached isn't always "counted once", the denominators are explained, the nearest-print tie goes to the tighter print, a test print can turn the knob's, wheel's or Estoa R1's check into a pass (counted per check), and Claude is introduced once as the author of the scoring calls labelled as Claude's.   - Counts after #20 (counted first prints): bridges 126 failed and 4 not graded (was 131 and 5), R6 0 failed and 3 not graded, R1 1 failed, 11 not graded, 16 passed.
- **Found while writing it.** 12 of the 18 first prints that fail the knob's R3 describe, in their own notes, a nut snapping past a lip, a springy mouth or slotted fingers narrower than the nut; 11 of them fail as a closed pocket. The check treats plastic as rigid, so a mouth the nut can't pass at the pocket's own size reads as closed. Round 3 printed two lip pockets a nut was pushed past (one held, one wouldn't take the nut), but nothing like these mouths, so no record decides them either way. The page says so under R3. No grader was changed here; whether these should be not graded instead is a scoring call left open. The tripod brief's table also still calls a bolt hole between 6.35 and 6.5 mm not graded, but the nearest-print rule now decides every such hole; the page describes the code.
