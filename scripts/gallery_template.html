What each model designed

Every design here came from one request and was graded by code against the prints on record. These are renders of what the models handed in. No model's design has been printed. Click a render to spin it.

Not graded means the records can't decide that case. It isn't a pass, and only decided results count as evidence of a limitation.

How the loop runs

Dan sets the rules and reviews. The session that started this one holds the key and relays his decisions. The loop session does one ladder step at a time, and every failure it reads either counts as a model's mistake or sends a fix back into the checks.

flowchart TD
  Dan(["Dan: rules, request wording, train review"]) -->|decisions| Start["Starting session: writes the charter, holds the key process"]
  Start -->|"charter and relayed decisions"| Loop["Loop session: one ladder step at a time"]
  Loop --> Build["Build the task: request, why it's hard, checks, reference, wrong designs"]
  Build --> Tests{"Tests: reference passes, each wrong design fails only its check"}
  Tests -->|no| Build
  Tests -->|yes| Review["Code review and readability"]
  Review -->|real findings| Build
  Review --> Queue["Model queue: only route to the key, budget capped"]
  Queue --> Models["12 models, each trial saved to results/runs"]
  Models --> Grade["Graders: pass, fail or not graded"]
  Grade --> Digest["scripts/digest.py: every trial's reasons"]
  Digest --> Readers["Sonnet subagents: read what the digest can't settle"]
  Digest --> Decide{"Model's mistake or the check's?"}
  Readers --> Decide
  Decide -->|"the check's: fix, test, changelog"| Regrade["Regrade saved trials, no new model calls"]
  Regrade --> Grade
  Decide -->|"the model's: real evidence"| Scoring["Walk the scoring criteria"]
  Scoring --> Log[".loop/LOG.md and a commit on this branch"]
  Grade --> Page["scripts/gallery.py: this page"]
  Log -->|next step| Loop
  Log --> Train(["Train review with Dan"])
  Page --> Train
  Train -->|"new rules and wording"| Dan
